WHAT THE SYSTEM IS:
  A 3-service Alzheimer's decision-support app:
    React frontend (:5173)  ->  Node/Express + MongoDB gateway (:5005, auth + patients)
                            ->  Python/Flask ML service (:5001)
    ML service = VGG-19 classifier + Grad-CAM++ + FSL biomarkers
                 + a RAG-grounded clinical rationale + a multilingual GPT-4o chatbot.


──────────────────────────────────────────────────────────────────────
0.  PRE-FLIGHT  (run ~10 min before the call, from the repo root)
──────────────────────────────────────────────────────────────────────
cd ~/vaidya-nidaan

lsof -ti tcp:5001 tcp:5005 tcp:5173 | xargs kill -9 2>/dev/null

# start all three services (leave this terminal open; Ctrl-C stops all):

cd ~/vaidya-nidaan

# In-domain retrieves at cosine ~0.3, off-topic at ~0.8, refusal floor sits at 0.75.

# (a) grounded, CITED answer from the medical knowledge base:
ml_service/.venv/bin/python ml_service/medical_rag.py "How does APOE4 affect Alzheimer's MRI biomarkers?"

# (b) adjacent-dementia differential — ANSWERS it (KB now covers Lewy body / FTD / vascular):
ml_service/.venv/bin/python ml_service/medical_rag.py "How does MRI help differentiate Lewy body dementia from Alzheimer's?"

# (c) the GUARDRAIL — out-of-scope question is refused (not hallucinated):
ml_service/.venv/bin/python ml_service/medical_rag.py "What is the capital of France?"

# (d) the EVAL harness (retrieval relevance + citation + refusal => 9/9):
ml_service/.venv/bin/python ml_service/eval_rag.py

# (optional) rebuild the knowledge base from PubMed/MEDLINE (NCBI E-utilities):
ml_service/.venv/bin/python ml_service/medical_rag.py --refresh

4.  RAW API CALLS  (if they want to see the service directly, not the UI)
──────────────────────────────────────────────────────────────────────
# every ML route needs the gateway's JWT now — grab a demo token first:

──────────────────────────────────────────────────────────────────────
5.  TROUBLESHOOTING
──────────────────────────────────────────────────────────────────────
- prediction fails "No trained Alzheimer model" -> check ml_service/.env
  ALZHEIMER_MODEL_PATH points to ml_service/models/alzheimer_vgg19_v2.keras , restart.
- 401 from :5001                   -> JWT_SECRET differs between the two .env files.
- "Address already in use"         -> free ports (step 0), re-run ./start-all.sh
- TensorFlow error mentioning protobuf ->
  ml_service/.venv/bin/python -m pip install "protobuf==5.29.6"
- FSL not found                    -> biomarker falls back to image-stats;
  ensure ~/fsl exists (fsl_available:true in /health).
- Data lives in MongoDB Atlas (db "vaidya_nidaan") — it persists across restarts.

  (Rotate the OpenAI key + HF token in the two .env files before sharing the repo.)
